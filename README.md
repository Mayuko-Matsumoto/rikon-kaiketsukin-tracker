# Settlement Tracker（分割債務・解決金 進捗管理＆自動リマインダーシステム）

個人間の分割合意金（離婚解決金・示談金・個人間融資など）における「毎月の支払期日管理」「入金実績の可視化」「期日到来・延滞時の自動リマインド通知」を一元管理するWebアプリケーションです。

## 📌 背景・解決したい課題（Why this project?）

個人間の分割支払い合意において、以下のような課題が頻繁に発生します。

1. **支払期日（月末営業日）のズレによる振込忘れ**
   - 「毎月末日払い（ただし土日祝日の場合は直前の営業日）」という取り決めにおいて、カレンダー上の祝日・週末判定が毎月異なり、支払側の認識ズレや遅延が発生しやすい。
2. **支払進捗・残高の不透明さ**
   - 「総額のうちいくら支払済みで、残り何回（何ヶ月）なのか」が双方にとって直感的に把握しづらい。
3. **手動での催促における心理的コストと遅延損害金の計算負荷**
   - 期日当日や延滞発生時に毎回手動で連絡する心理的負担が大きく、また延滞日数に応じた遅延損害金（日割り計算）を正確に算出する手間がかかる。

これらを解決するため、**厳密な日本の営業日（土日祝）判定ロジック**と**冪等性を担保した自動通知バッチ**を備えた管理システムを構築しました。

## ✨ 主な機能（MVP）

- [ ] **月末営業日（支払期日）の自動算出機能**
  - 指定月の末日が土曜・日曜・日本の祝日である場合、直前の平日（営業日）を支払期日として自動判定
- [ ] **返済状況ダッシュボード**
  - 総額、支払済金額、残高、残り支払回数（ヶ月）、完済予定日のプログレス表示
- [ ] **延滞ステータス＆遅延損害金シミュレーター**
  - 期日超過時のアラート表示および延滞日数に応じた遅延損害金（年利・日割り）の自動算出
- [ ] **LINE自動リマインド通知（冪等性対応）**
  - 支払期日当日の朝および期日超過時にLINEボットから自動通知（DBの通知ログにより同日の二重送信を防止）

## 📐 コアロジック設計（疑似コード）

### 1. 月末営業日（給料日）判定ロジック
```text
関数 GetPaymentDueDate(対象年, 対象月):
  1. 対象年・対象月の「月末日（最終日）」を取得する
  2. ループ処理:
     もし 現在の判定日 が「土曜日」または「日曜日」または「日本の祝日」である場合:
       判定日 を 1日前（前日）にずらす
     そうでなければ（平日の場合）:
       ループを抜ける
  3. 判定日 を「今月の支払期日」として返す
```

### 2. 遅延損害金（日割り）計算ロジック
```text
関数 CalculateLateFee(未払元本, 年利率, 支払期日, 現在日):
  1. もし 現在日 <= 支払期日 ならば:
       延滞なしのため 0円 を返す
  2. 延滞日数 = 現在日 - 支払期日（日数の差分）
  3. 遅延損害金 = 未払元本 × 年利率 × (延滞日数 / 365) ※端数は切り捨て（整数演算）
  4. 遅延損害金 を返す
```
